# S3 storage and local setup

## Configuration

Credentials use the standard AWS SDK chain: environment, shared profiles, or
workload/instance roles. S3 credentials belong only in the host environment, never
in a plugin. The host accepts any registry identity served by a compatible plugin.

`--endpoint`, `--region`, `--path-style`, `--bucket`, and `--prefix` configure S3.
Path-style addressing defaults to true for compatible backends; use
`--path-style=false` if your provider requires virtual-host addressing. Set the
signing region expected by your provider. Local development uses rclone and automated tests use GoFakeS3; AWS S3,
R2, and other providers can use their respective endpoints and credentials, but
provider-specific deployments have not all been tested.

Required bucket permissions: read object metadata (`s3:GetObject`), write objects
(`s3:PutObject`, including multipart creation/completion), and
`s3:AbortMultipartUpload`. Grant `s3:ListBucket` on the bucket so missing-object
HEAD requests return 404 instead of ambiguous 403 responses. The bucket is not
created automatically. Optional SDK checksums are disabled for compatibility;
`dug` computes SHA-256 itself before upload.

## Local S3 setup

With [rclone](https://rclone.org/install/) on your PATH (`brew install rclone`), use
`just local` to run a job against a persistent local S3 server. No separate S3 command, bucket creation, or credential exports are needed.

Start the registry plugin in one terminal:

```sh
unset DUG_PLUGIN_TOKEN
just plugin wordpress --listen 127.0.0.1:7781
```

Run the downloader in another terminal:

```sh
just local sync wordpress \
  --option slugs=akismet,wordpress-seo \
  --order downloads --limit 2

# The same wrapper works for separate listing and download stages.
just local list wordpress --limit 100
# Full references as JSONL; progress and saved-file locations remain on stderr.
just local list wordpress --limit 20 --format jsonl
just local download wordpress --inventory INVENTORY_KEY --order downloads --limit 20

# Optional bucket selection; the wrapper creates it if missing.
just local sync wordpress --bucket my-local-corpus --option slugs=akismet
```

The built binary supports the same wrapper: `./bin/dug local sync wordpress ...`.
All normal filtering, limits, concurrency, and version-depth flags apply. Registry
plugins still run separately; select another plugin with `--plugin-url` as usual.

Before a job, the wrapper checks whether anything answers on 127.0.0.1:9000. If not,
it starts `rclone serve s3 data --addr 127.0.0.1:9000` detached (logging to
`logs/rclone.log`), waits for it to answer, and creates the selected bucket (default
`dug-e2e`) if missing. The server binds to loopback only because its credentials are
fixed. Buckets are directories under `data/` in the working directory and objects are
plain files, so `data/<bucket>/<key>` can be inspected with ordinary tools. `just` runs
from the repository root; use the same working directory when running the binary.
If another S3 server already owns port 9000 (for example an old `dug-rustfs`
container: `docker stop dug-rustfs`), the job fails at the bucket check with a 403.

Local mode uses `http://127.0.0.1:9000`, region `us-east-1`, path-style addressing,
and credentials `dug` / `dug`. It ignores `DUG_BUCKET`,
`DUG_S3_ENDPOINT`, `AWS_REGION`, and AWS credential environment values; use
`--bucket` to select a different local bucket. Endpoint/region/addressing overrides
are rejected in local mode. Regular `just dug` commands retain their existing
configuration behavior. Help and invalid arguments do not start S3.

The server stays running after a job, and data/logs persist in directories ignored
by Git. ZIPs come from WordPress and are stored intact as S3 blobs; rerunning a job
skips completed versions.

```sh
tail -f logs/rclone.log
pkill -f 'rclone serve s3'   # the next local job starts it again
```

`just s3` runs the same server in the foreground if you prefer to manage it yourself.
Data written by the old RustFS container uses RustFS's own on-disk layout and is not
readable as objects through rclone; use a fresh `data/` directory.

### GoFakeS3 test backend

[GoFakeS3](https://github.com/johannesboyne/gofakes3) remains available without
Docker for lightweight tests:

```sh
just s3-fake --listen 127.0.0.1:9000 --data .local/s3.db --bucket dug-e2e
```

Stop any other server on the same port first. This server runs in the foreground,
automatically creates the bucket, and persists objects in `.local/s3.db`. It only
binds to loopback and does not enforce authentication; set `AWS_ACCESS_KEY_ID=local`
and `AWS_SECRET_ACCESS_KEY=local` for the host. Stop it with Ctrl-C. Only one server
can open the same database at a time.
